## Classify the script

Choose the primary performance context:

- Talking-head video
- Voiceover
- Product demo
- Webinar host or presenter
- Interview or fireside prompts
- Teleprompter script
- Event opening, transition, or closing
- Speaker notes for an existing visual artifact

The script must fit how it will be performed and edited.

## Script state

Record:

```text
format and platform
target duration
speaker or host
audience
desired outcome
visuals or screen actions
demonstration dependencies
CTA
required facts or disclaimers
tone
fallbacks
```

## Beat sheet before prose

Define beats in this form:

```text
time range
beat job
spoken point
visual or action
proof or example
transition
```

Do not write a polished paragraph until the sequence works.

## Spoken lines

- Use language the speaker would naturally say.
- Keep one thought per sentence where possible.
- Put important words early.
- Avoid stacked subordinate clauses.
- Do not repeat what is obvious on screen.
- Let visuals carry visual information.
- Write exact lines only where wording matters. Use beat notes where improvisation will sound better.

## Stage directions

Separate stage or production directions from spoken copy.

Use labels such as:

```text
[ON SCREEN]
[DEMO]
[PAUSE]
[SLIDE]
[B-ROLL]
[HOST NOTE]
[FALLBACK]
```

Do not make the speaker read stage directions accidentally.

## Product demo graph

```text
user goal
-> starting state
-> smallest visible success
-> meaningful next action
-> proof of result
-> failure or edge case
-> CTA
```

Define:

- Accounts and permissions required
- Data or environment required
- Expected load times
- Known unstable steps
- A pre-recorded or screenshot fallback
- What the speaker says while waiting

Do not narrate every click. Explain decisions and outcomes.

## Talking-head and voiceover graph

```text
hook with substance
-> context
-> core claim or task
-> example or proof
-> implication
-> action
```

Avoid generic greetings, artificial suspense, and a conclusion that repeats the hook.

## Webinar behavior

Account for:

- Host handoffs
- Audience questions
- Polls or chat prompts
- Screen-sharing transitions
- Time zones and exact dates when relevant
- Recorded viewers who cannot participate live

Write a recovery line for silence, delayed responses, or technical problems.

## CTA

Make the CTA proportionate to the content and audience readiness.

Examples:

- Try one exact step
- Download a resource
- Register or attend
- Read the full guide
- Compare a result
- Start a trial

Do not add multiple competing CTAs unless the format requires them.

## Timing

Estimate spoken duration and reserve space for visuals, clicks, reactions, and pauses. Teleprompter scripts can be denser than live demos, but should still sound spoken.

## Default deliverable

Return a performance-ready script with:

1. Duration and assumptions
2. Beat or time markers
3. Spoken copy
4. Visual and stage directions
5. Fallback notes for demos or live segments
6. CTA
7. Source notes outside spoken lines when needed
